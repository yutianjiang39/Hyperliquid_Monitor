# Hyperliquid Local · 本地 Python 终端窗口版 v2.3.2（回撤百分比与大小图切换版）

查看 Hyperliquid 单钱包的逐笔盈亏、仓位、账面资产与参考杠杆，支持本地缓存、AWS 历史回填和离线报告。

程序在你的电脑上运行。终端窗口不依赖 Claude/OpenAI 账号或模型 API；公开 Hyperliquid 查询不需要钱包私钥。第一次安装依赖及更新真实数据需要联网，已生成报告、缓存重算和模拟演示可以离线运行。

**首次查看：** 本包保留原钱包历史缓存和窗口索引，未附带历史报告。安装依赖后，在项目虚拟环境中运行 `python app.py report --open`，或在终端界面选择“生成报告”，即可从缓存离线重建；最近报告摘要也会随之恢复。需要更新真实数据时运行 `assets` 或 `run`。模拟数据使用独立目录。

### v2.3.2 更新

**每段回撤增加起点资金百分比。** 累计已实现盈亏图的每段回撤同时显示下降金额与百分比，计算如下：

```text
回撤金额 = 该段累计已实现盈亏峰值 − 该段累计已实现盈亏谷底
回撤百分比 = 回撤金额 ÷ 峰值同一事件时的 USDC 账面资金 × 100%
```

分母固定为该段回撤开始时的资金，优先取该事件的**连续可核对余额**；该项缺失时，使用同一事件的**已知流水重建参考余额**，并在页面标明“参考”。切换资产图到官方账户净值或官方永续净值不会改变这个分母。展开回撤详情可核对起点资金和来源；资金未知、为零或为负时保留回撤金额并说明百分比不可计算的原因。各段仍按回撤金额排序。例如，回撤起点资金为 20,000 USDC、该段已实现盈亏下降 2,000 USDC，回撤百分比就是 10%。

**四张图都可一键切换大图或小图。** 图表区提供全局切换，每张图也有独立按钮。大图使用更宽、更高的绘图区，并按实际尺寸重新绘制曲线、坐标和标注；切换时保留当前时间范围、计算口径和选中事件。回到小图后继续使用原有紧凑布局。大小图仅改变显示尺寸，与“放大该段”等改变时间范围的操作分别使用。

升级后运行 `python app.py report --open` 生成新版报告；已生成的旧 HTML 不会自动更新。本次保留原缓存数据，项目包不附带生成报告。

### 新增图表标注

四张图增加随当前时间区间和所选计算口径更新的统计标注。通过“图上标注”按钮可显示或隐藏图上的辅助标记，图下统计摘要始终保留；鼠标读数、方向键和原有四图联动继续可用。

| 曲线 | 新增信息 |
| --- | --- |
| **累计已实现盈亏** | 标出最多三个最大回撤区间，按峰值到谷底的 **USDC 下降金额**排序，同时显示**回撤金额 ÷ 起点资金**的百分比；显示峰值、谷底、恢复时点和持续时间，并区分“已恢复”“区间末未恢复”“缺口截断 · 恢复未知”。可定位关键点或放大该段。零点位于纵轴范围内时显示零值参考线。 |
| **同时持仓规模** | 中位数虚线、Q1–Q3 中间 50% 分布带和峰值标记，帮助比较常见仓位规模与峰值。 |
| **账面资产与净值** | 中位数虚线、区间高低点、首尾有效点差额。差额包含转入转出等资金影响，不代表投资收益。 |
| **参考杠杆** | 中位数虚线、Q1–Q3 中间 50% 分布带及峰值标记；分母和仓位口径切换后同步重算。 |

**回撤按独立的一轮计算。** 从一个峰值开始，直到重新达到或超过该峰值，属于同一轮回撤；其中的多次局部下跌不会重复占据前三名。区间结束时仍未恢复的回撤也参与排名；遇到缺失值则结束该段，并标为“缺口截断 · 恢复未知”，不跨缺口推断恢复。实际只有一段或两段时只展示相应数量，没有回撤时明确提示。计算从当前区间的首个有效点或缺口后的首个有效点开始，不补造期初零值，也不向区间外追溯旧峰值。累计盈亏可为负；百分比的分母始终使用回撤起点的正值账面资金。该比例表示这段已实现盈亏下降占起点资金的比例，不代表包含浮盈亏及全部资产估值的账户净值回撤。

**统计仅针对当前区间的有效点。** 中位数及分位数给每个有效事件点或采样点相同权重，零值参与、缺失值排除；分位数使用排序后的线性插值。它们不是按停留时长加权，交易密集时段或更密的采样会影响分布。统计使用全部可用点，不通过抽样减少记录。切换日期会重算标注，但不会重置原曲线的累计盈亏。

新增统计在浏览器内离线计算，不增加运行依赖。原有 CSV、原始 Decimal 精度与账务计算口径保留。升级后请重新运行 `python app.py report --open`；以前生成的 HTML 不会自动获得回撤百分比、大小图切换及新标注。

### 四张曲线与默认口径

| 曲线 | 默认计算方式 | 读图要点 |
| --- | --- | --- |
| **逐笔已实现盈亏** | `Σ closedPnl`；扣交易费模式为 `Σ(closedPnl − fee)` | 每次减仓、清仓、反手平旧仓及时入账，不按天合并。扣费模式也包含开仓费；资金费独立统计，不计入这张交易盈亏图。 |
| **仓位规模** | `Σ abs(持仓数量) × 平均开仓成本`；也可选各市场最近观察到的成交价 | 多空绝对值相加。可从连续成交和官方已实现盈亏核对的期初成本会恢复，并保留重建标记；真实缺口仍留空。两种金额均不是当时的标记价格市值。 |
| **账面资产** | 从余额基准点逐笔反推的 **USDC 已知流水余额参考** | 纳入目标地址现货和所有已确认 USDC 结算永续的 USDC 资金变动；不含未实现盈亏、非 USDC 现货及金库/借贷投资市值，不等于可提现余额。 |
| **参考杠杆** | 所选仓位规模 ÷ 同一事件时刻的 USDC 账面余额参考 | 分子仍是已覆盖的 USDC 永续仓位。分母非正、仓位不明或超出已核实成交覆盖时留空；这不是全钱包净资产杠杆，也不是交易面板中的单仓杠杆设置。 |

资产图可切换到“账面余额 · 连续可核对”、官方账户净值、官方永续净值。杠杆也保留旧的官方净值采样模式。两类数据不混用：**账面余额与包含浮盈亏的官方净值各自保留名称、来源和计算口径。**

交易盈亏与仓位仅汇总已覆盖的 USDC 永续（含 HIP-3，保留 DEX 前缀）；现货成交仍参与 USDC 资金收付计算，但不当作永续仓位。非 USDC 或币种未知的市场保留在明细中，不擅自折算。未在数据中出现的历史持仓无法凭空补全。

### 账面余额怎样反推

对于同一地址、同一 USDC 资金范围：

```text
账面变动 = 净转入 + 已实现盈亏 + 资金费净收入 − 手续费 + 其他现金变动
历史账面余额 = 已知基准余额 − 从该历史时刻之后至基准时刻的账面变动
```

USDC 现货买卖收付也属于资金变动；同地址现货/永续之间的资金搬移在此范围内抵消。永续开仓占用保证金不按整笔名义价值扣减资金。借入资金会增加现金余额，但相应负债没有从本曲线扣除，因此借贷现金余额不等于净资产。

只要有可靠余额基准及该段完整流水，就可重建这一段，不必先拿到开户以来的全部记录。若缺失交易盈亏、手续费、资金费、转账解释或连续性，默认曲线继续展示**仅按已知贡献反推的参考值**，同时标记误差来源；严格模式会在无法核对的部分留空。

**自动余额基准始终是估算基准。** 程序读取账户模式、现货 USDC 余额、各 USDC 永续 DEX 的账户/仓位快照和未实现盈亏，按对应账户模式推导 USDC 账面资金。多个 HTTP 响应不是同一时刻的原子快照；即使连续两轮结果接近，也不会因此证明余额准确。自动基准保留 `validated: false`，默认用于已知流水参考线。

**严格模式需要已核验基准。** 如有经过独立核对的同口径余额，可用 `import --kind balance` 导入。`validated: true` 是导入者已完成核验的声明，不会让任意净值或估计数自动变成可靠余额。严格模式还要求基准到该时点之间没有已识别的未知贡献；它也不证明交易所/API 已提供全部历史。导入格式见第 7 节。

平仓只是将浮盈亏结算到账面：它可能使账面余额跳变，但不能将这笔已实现收益再次记作账户净值新增收益。本版不取历史 K 线、不重建持仓期间浮盈亏；官方净值保留真实采样点，不以余额线冒充真实净值路径。

### 更密的事件轴与日期按钮

四图共享成交、资金费、转账及资产采样的联合事件时间轴；同毫秒成交仍分别保留。每图显示“有效点 / 总点数”，可用鼠标、方向键、“上一点 / 下一点”和事件序号查看。没有数据支持的历史阶段仍保留缺口，不通过插值增加虚假的观测点。

首次打开聚焦已有成交覆盖的时间区间；“全部”显示完整缓存范围。最近 **7 / 30 / 90 / 180 / 365 天**均以**报告最后一个数据时刻**为终点，并限制在可用范围内。它们不是以打开网页时的电脑时间为终点，也不会触发网络请求。浏览器缩放只改变查看范围，不重置累计盈亏；命令行设置新分析窗口再生成报告时，盈亏才从该窗口起点重新累计，仓位用可用的更早缓存恢复。

**费用只扣一次。** 官方 fill 的 `fee` 已含 `builderFee`，负费用为返佣；不会再次扣 builderFee。币种未知或非 USDC 的费用不擅自当作美元。资金费在资产资金流水中计入，交易盈亏图仍保持独立。字段依据见[官方 Info API](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint)、[开仓均价与盈亏规则](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/entry-price-and-pnl)。

**保留的官方净值模式。** `portfolio.accountValueHistory` 包含其账户范围内的未实现盈亏及其他估值，程序合并各窗口并保留真实采样。旧参考比率仅使用不晚于事件的净值，超出默认 24 小时、权益非正或仓位未知时留空；不会把未来净值倒填进这个模式。与此不同，账本余额反推允许使用后面的余额基准，属于事后复盘数据，不能直接当作无未来信息的实时策略输入。见[官方净值采样说明](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/portfolio-graphs)。

**账户范围始终是目标 HyperCore 地址。** 子账户、Vault 自有地址、HyperEVM 和其他链资产不会自动合并。统一账户与标准账户的余额组合方式不同，不能把每个 DEX 的重复余额相加。口径依据见[账户模式说明](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/account-abstraction-modes)、[Spot API](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint/spot)。

## 1. 快速启动

需要 **Python 3.10+，推荐 Python 3.11 或 3.12**。请先完整解压到可写文件夹，不要直接在压缩包中运行。

### Windows

1. 安装 Python，并在安装时启用 **Add Python to PATH**。
2. 双击 `start_windows.bat`。
3. 首次运行自动创建项目专用 `.venv` 并安装依赖；随后进入终端窗口。
4. 建议把窗口放大到至少 **100 列 × 30 行**，120 × 40 更舒适。Windows Terminal、PowerShell 或正常命令提示符均可作为终端宿主。

如果需要分开安装/启动，可先双击 `install_windows.bat`，再启动。安装器只使用已有 Python，不安装 Python 本体，不请求管理员权限。

### macOS

安装 Python 后，可双击 `Start_macOS.command`。也可以在终端进入解压目录运行：

```bash
bash start_macos_linux.sh
```

首次运行同样会自动创建 `.venv`、安装依赖。如果系统默认 `python3` 版本较旧，可指定已安装的解释器：

```bash
HL_PYTHON_BIN=/path/to/python3.12 bash install_macos_linux.sh
bash start_macos_linux.sh
```

### Linux

在解压目录的终端中运行：

```bash
bash start_macos_linux.sh
```

部分发行版需要先安装其 Python venv 支持包，具体以 `python3 -m venv` 的提示为准。

**请使用终端窗口，避免 IDE 的纯文本输出面板或 Jupyter 输出区。** 它们通常无法提供交互终端所需的键盘、尺寸和鼠标事件。

## 2. 窗口中可以做什么

- 输入目标钱包、UTC 起止日期、AWS profile、每轮下载预算。
- **API 抓取**：更新可见成交、资金流水、资金费、官方净值、账户模式和 USDC 余额估算基准，再生成四曲线报告与本地分页视图。
- **更新资产历史 + 四曲线**：更新官方净值、账户模式和余额估算基准，并增量补成交、资金费与转账至余额基准之后，再生成报告。此操作会联网读取成交与流水，不只请求 portfolio。
- **归档清单**：列出官方 S3 实际可用对象、文件数和待下载压缩体积。
- **归档扫描**：确认清单及 requester-pays 费用后开始下载；达到预算暂停，重跑可续传。
- **导入文件**：合并目标钱包的 JSON / JSONL / CSV，按类别选择 fills、ledger、funding、portfolio 或 balance；净值和已核验余额也可分别用命令行 `import --kind portfolio`、`import --kind balance` 导入，格式见下文。
- **生成报告**：只使用本地缓存和已有余额基准重算，完全离线；没有余额基准时保留提示，可先联网运行 `assets`，或导入已核验余额。
- **演示**：不填钱包、不联网也能体验；数据被明确标成模拟数据，并与实际钱包缓存隔离。
- **停止**：在安全检查点停止后台任务，保存已经提交的记录与完成文件检查点。当前网络请求可能需要等待超时，计算/报告阶段在阶段结束时检查停止请求。
- 窗口中切换操作、战绩、转账、资金费和覆盖范围；每页最多 **50 行**，搜索通过 SQLite 执行。
- 查看实时日志、打开最近生成的 HTML 报告。

终端界面只保留有限日志和当前页，不把全部成交渲染进窗口。报告仍使用之前的分片加载方案，默认每片 1,000 条、每页 50 条。

底部命令输入框也可直接操作，输入后按 Enter：

| `/api` | 读取 API 并生成报告 |
| `/assets` | 更新官方净值与余额基准，增量补流水并重建四曲线 |
| `/plan` | 查看归档清单确认提示 |
| `/scan` | 按已有清单、预算扫描归档 |

## 3. 推荐使用顺序

1. 第一次先运行“演示”，确认终端显示和本地文件权限正常。
2. 填入真实目标钱包，运行“API 抓取”。不要填写 API agent 地址、私钥或助记词。
3. 若要回补更早历史，导入已有历史导出，或设置标准 AWS 凭证后列归档清单。
4. 查看清单体积，再扫描归档。每轮默认 10 GiB，达到预算后续跑同一清单；它是压缩字节预算，不是账单金额上限。
5. 在表格中查看数据，或打开报告。HTML 报告目录中的 `data`、`exports`、`audit` 文件夹需要一起保留。

本次包内保留原钱包成交缓存。运行 `python app.py assets --open` 可更新资产历史、余额估算基准，并增量补成交/资金费/转账到该基准之后。`run` 执行常规数据更新及余额刷新；`report` 完全离线，只使用缓存。余额反推需要历史时点与余额基准之间的完整流水，因此即使报告截止日较早，`assets` 也可能缓存该截止日之后、到当前余额基准为止的记录；报告所选展示区间不因此改变。

报告通过浏览器 `file://` 打开本地 `index.html`，不需要启动网页服务器。可以查看逐笔变化并使用报告提供的筛选、缩放和明细；关闭浏览器不会删除缓存。

开始日期留空表示来源能提供的最早记录。结束日期留空表示任务开始时刻。
配置中的日期使用 **UTC**；报告中的表格使用北京时间。截止只填 `2026-01-01` 代表该日零点，要包含整天请写 `2026-01-01T23:59:59.999Z`。

## 4. “全部历史”的实际边界

官方文档标注 `userFillsByTime` 每次最多 2,000 条、最近 10,000 条的可用范围；实际响应或已有缓存可能更多，程序按真实返回保留全部已获得记录，不承诺接口返回钱包的全部历史。更早数据通过官方归档或已有导出补充。TWAP、非资金费流水和资金费分开读取，成交会合并去重。限制和分页字段见[官方 Info API](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint#retrieve-a-users-fills-by-time)。

官方归档前缀：

- `node_fills_by_block`、`node_fills`：新旧完整 fill 格式。
- `node_trades`：更早旧格式，缺少官方 `closedPnl` / fee 时保留未知。
- `misc_events_by_block`：可识别的转账、资金费等非成交事件；未知目标事件保存在审计输出，标明解释缺口。

程序显示 API 可见范围、归档清单范围、已扫描对象、缺失小时、未知字段和失败对象。**“清单扫描完毕”不自动等于钱包终身历史被证明完整。**

范围是目标 **HyperCore 单地址**的成交/仓位变化/资金流水/资金费。子账户、Vault 自有地址分别运行；未成交撤单、每次杠杆变更、HyperEVM 或其他链通用钱包动作不自动包含。

## 5. AWS：本地凭证配置

使用 Boto3 的标准 AWS 凭证链：已有 profile、环境变量或标准凭证文件。界面中的 profile 填已有配置名称，留空使用默认凭证链。程序配置文件只保存 profile 名、区域和预算，**不保存 access key、secret key 或 session token**。

如果你已安装 AWS CLI，可用其标准配置方式建立专用 profile：

```bash
aws configure --profile hyperliquid-history
```

然后在窗口 profile 中填 `hyperliquid-history`。没有 AWS CLI 时也可按 Boto3 官方凭证文档设置标准环境变量/凭证文件；AWS CLI 不是运行本程序的必要依赖。

官方 S3 是 requester-pays 数据来源。**列清单可能有请求费用，下载产生传输/请求费用。** 按钱包筛选仍要下载、解压全市场文件；不是只收取目标钱包的几 KB 数据量。预算按计划压缩字节估算，重试等费用另计。

每次归档清单固定起止时间。稍后续传使用同一范围；要补到更新时刻，请重新列清单。配置起止日期变更后，过期清单不能直接用于付费扫描。

## 6. 本地文件与续传

默认目录相对 `config.json` 所在位置解析，而不是当前终端目录：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 首次保存后生成，包含钱包、日期、目录、AWS profile 和预算 |
| `data/钱包地址/wallet_history.sqlite` | 去重后的原始缓存、API 游标和归档检查点 |
| `data/钱包地址/archive_plan.json` | 归档清单，绑定钱包与冻结时间范围 |
| `data/钱包地址/views.sqlite` | 窗口分页索引，生成报告时更新 |
| `data/钱包地址/last_report.json` | 生成报告时写入的最近报告路径和汇总 |
| `data/demo/` | 独立模拟演示缓存 |
| `reports/` | 运行后生成的独立 HTML 报告目录和 ZIP |

官方净值各窗口、账户模式、余额基准、采集分项、来源与诊断均保存在该钱包 SQLite 缓存中。刷新失败保留此前数据并显示原因，不会把错误当作零余额。服务器旧净值可能较粗，程序继续保留此前已缓存的真实细采样。余额基准早于或晚于所需流水覆盖时，会单独标记，不能据此假定区间无交易。

每个报告的 `exports/` 另外包含以下曲线数据：

| 文件 | 内容 |
| --- | --- |
| `event_curve.csv` | 每笔操作的毛/净已实现盈亏、累计值、成本/最近成交价仓位规模及质量标记 |
| `equity_curve.csv` | 官方永续和综合账户净值、时间戳与来源窗口 |
| `leverage_curve.csv` | 保留的官方净值模式参考比率、净值时间、快照年龄与缺失原因 |
| `timeline_curve.csv` | 联合事件轴：每个成交/资金事件时刻的盈亏、持仓、余额与参考杠杆状态 |
| `balance_curve.csv` | 严格及已知流水参考余额、当笔变动、基准时间/来源与质量标记 |
| `balance_leverage_curve.csv` | 以两种余额口径为分母的成本/成交参考价杠杆，保留非正分母及未知仓位缺口 |
| `cash_flow_events.csv` | 实际用于余额重建的已知金额、未知贡献、事件类型与解释标记 |

`audit/portfolio_history.json`、`portfolio_meta.json`、`portfolio_latest_raw.json`、`portfolio_provenance.json` 保留官方净值输入；`audit/balance_anchors.json`、`balance_anchor_meta.json`、`balance_anchor_latest_raw.json` 和 `balance_diagnostics.json` 保留余额基准、分项快照及对账诊断。所有曲线也汇总在 `exports/curves.json`，包含计算口径与覆盖提示。CSV 时间戳为整数毫秒，报告显示北京时间。

关闭电脑或窗口后，已经提交的缓存仍保留。再次选择同一钱包和缓存目录即可继续。
同一钱包缓存有进程级运行锁，避免两个终端同时更新相同数据；正常退出或进程结束后锁自动释放。
备份时先停止任务/关闭程序，再复制该钱包的缓存目录。不要把整个 `.venv` 复制到其他系统，重新安装依赖即可。

## 7. 命令行模式

窗口之外，同一程序也支持命令行。下面以激活项目虚拟环境后的 `python` 为例；未激活时可使用 `.venv/bin/python`，Windows 使用 `.venv\Scripts\python.exe`。

```bash
python app.py --help
python app.py doctor
python app.py demo --open
python app.py init --wallet 0x你的钱包地址
python app.py run --open
python app.py assets --open
python app.py plan --profile hyperliquid-history
python app.py scan --accept-requester-pays --budget-gib 10
python app.py import history.jsonl --kind fills
python app.py import portfolio.json --kind portfolio --open
python app.py import verified_balance.json --kind balance --open
python app.py report --open
```

常用三种任务：`run` 更新成交等数据、官方净值及余额基准；`assets` 更新资产/余额基准并增量补齐到基准时刻后的可见流水；`report` 完全离线。`demo` 使用独立模拟数据及明确给定的初始资金，不与真实钱包缓存混合。

精简版未附带测试文件；帮助中的 `self-test` 是开发检查入口，需使用原完整版。

#### 导入官方净值历史

可以直接导入官方 `portfolio` 响应的原生 JSON 数组。若文件有包装，支持以下结构；`wallet` 可用 `user` 代替，填写后会核对是否与当前钱包一致：

```json
{
  "wallet": "0x你的钱包地址",
  "user_abstraction": "unifiedAccount",
  "portfolio": [
    ["allTime", {"accountValueHistory": [[1730000000000, "10000.25"]], "pnlHistory": [], "vlm": "0"}]
  ]
}
```

上例中的钱包占位符必须替换为实际 42 字符地址；账户模式应填真实来源的模式。只导入原生数组、且没有此前成功核实的模式时，净值可绘制，杠杆参考比率保持未知；联网运行一次 `assets` 可获取模式。

CSV 支持以下格式，`pnl` 列可省略；`time` 为整数毫秒或带时区的 ISO 时间。必须提供 `window`，避免混淆永续与综合净值：

```csv
window,time,account_value,pnl
perpAllTime,1730000000000,10000.25,120.00
allTime,1730000000000,15000.25,130.00
```

```bash
python app.py import portfolio_samples.csv --kind portfolio --open
```

仅 `fills/ledger/funding` 导入使用 `--timestamp-unit`；portfolio CSV 时间须按上述格式填写。不合法数值不会补零；有效历史按窗口和时间合并，原缓存中不同时间的点会保留。

#### 导入已核验的 USDC 账面余额

创建 JSON 文件，例如 `verified_balance.json`：

```json
{
  "wallet": "0x你的钱包地址",
  "anchors": [
    {
      "time": 1730000000000,
      "balance_usdc": "10000.25",
      "scope": "hypercore_usdc_cash",
      "validated": true,
      "source": "人工核验的余额记录"
    }
  ]
}
```

```bash
python app.py import verified_balance.json --kind balance --open
```

以上金额和时间仅为格式示例，请替换成该钱包真实核验过的记录。`wallet` 必须是当前目标钱包的实际 42 字符地址，`time` 为整数毫秒；金额建议以十进制字符串保留精度。一个文件可提供多个基准点。

`scope` 的含义是**同一 HyperCore 地址的 USDC 账面资金，涵盖现货及 USDC 永续，包括占用/隔离保证金，不含未实现盈亏与其他投资资产估值**。不能填可提现额度、包含浮盈亏的综合净值、某个单独 DEX 的不完整余额，或其他币种折算资产。存在借贷时，本口径记录现金，不宣称已经扣除对应负债。

`validated: true` 仅用于你确实已经核对过时间、金额及完整账户范围的基准；不要为了让严格模式出图而给自动估计结果加此标记。多个基准若不能与中间已知流水对上，程序保留差异诊断，不把误差悄悄平摊到历史曲线中。

自定义配置文件可放在命令前或后：

```bash
python app.py --config work/config.json run
python app.py run --config work/config.json
```

一次执行 API、清单与按预算归档扫描：

```bash
python app.py run --archive --accept-requester-pays --budget-gib 10 --open
```

建议首次单独运行 `plan`，看清实际体积后再下载。`--json` 让结果写 stdout、进度写 stderr，便于脚本调用。
退出码：0 完成所选任务；1 错误；2 用法/终端环境问题；3 部分失败或预算暂停；130 用户停止。
任务完成仍应检查报告的数据覆盖状态，不能把退出码 0 当作终身历史完整证明。

## 8. 计算口径与大数据表现

账务引擎使用 Decimal 精度，支持开加减清分类、反手拆分、同毫秒区块顺序、重复记录合并和缺失开仓段标注。
完整且净盈亏已知的已平仓回合才进入胜率；分母包括保本回合。`fee` 已包含 builderFee，不重复扣除；资金费独立统计。
现货与合约分开，不同保证金币种不强行混算为 USDC；未知盈亏、费用或币种保持未知。

成本重建只使用可核对的成交价、减仓数量、官方已实现盈亏及连续仓位链，保留是否使用了后续成交的信息。它不反过来用猜测的成本制造缺失官方盈亏。联合事件轴使已知状态随真实资金事件延续；不同来源在同毫秒内顺序不确定时明确标记。

`src/balance.py` 负责流水与余额反推，`src/balance_snapshot.py` 负责余额基准采集/导入，`src/event_timeline.py` 负责统一事件状态与余额参考杠杆，`src/report_template.html` 负责四图联动和日期预设，`src/chart_insights.js` 负责图表统计与独立回撤区间计算。

HTML 主文件只放汇总和分片目录，按需加载数据；搜索跨全部分片进行。终端窗口查询本地索引，只展示一页。
全局搜索仍与数据量有关；分析极大量成交仍需要相应内存、磁盘和时间。

本包附带图表统计的独立开发检查，可选运行 `node tests/chart_insights.test.cjs`。使用应用和离线报告不需要安装 Node.js。精简包不包含原有 Python 开发测试集，`app.py self-test` 仍需原完整版的测试文件。

## 9. 常见问题

**找不到 Python / 版本太旧**：安装 Python 3.11/3.12，再重开终端；Windows 检查 PATH。启动器不会自动下载安装 Python 本体。

**第一次安装失败**：先查看终端保留的错误，确认能访问 Python 包源。不要跳过依赖错误强行启动；修复后重新运行安装脚本即可。

**窗口较窄、按钮显示不全**：放大终端或缩小字体；设置区可滚动，推荐 120 × 40。

**终端显示方块字或对齐异常**：使用支持中文和等宽字符的终端字体，并保持 UTF-8。Windows 启动器会设置 UTF-8。

**按停止没有立刻消失**：程序正等待当前网络请求或一个分析/写报告阶段结束；停止按钮会设置取消请求，在安全检查点提交并关闭缓存。

**AWS 没权限、403 或无凭证**：这是归档身份/权限问题，不会当成“没有历史”；API/导入/演示仍可使用。

**只看到最近数据**：普通成交 API 的保留范围如此，请合并归档或历史导出。

**默认账面资产图为空**：先运行 `python app.py assets --open`，检查余额基准是否成功读取，以及基准前后的流水是否已缓存。若仍无可靠可用基准，程序保留空值，可导入已核验的同范围余额。不会把官方综合净值直接冒充余额。

**严格余额图为空，但默认参考线有值**：自动余额基准来自非原子快照，保持 `validated: false`，这是预期区别。严格模式需要已核验导入基准，并且区间中没有已识别的未知贡献；默认参考线保留快照和流水误差提示。

**杠杆图仍有缺口**：余额不大于零、持仓未知、真实成交缺口或超出已核实成交覆盖时都不能正常计算。官方净值模式还受默认 24 小时快照时效限制；余额模式不因官方净值稀疏而套用这个时效门槛。

**旧资产点与新余额线数值不同**：官方净值含未实现盈亏并可能包含其他资产，USDC 账面资金使用不同范围。检查来源和范围，不应强制把两者对齐。

**两种仓位规模不同**：最近成交价只是每个市场最后一次已观察成交价格，期间没有交易就不重估；它不是当时的标记价格。成本仓位更适合查看开加减清的规模变化。

**只复制 HTML 后没有明细**：请完整解压报告 ZIP，保留相邻 `data/exports/audit` 目录，再打开 `index.html`。

**钱包为空/无记录**：确认是实际账户地址；API agent 地址和子账户地址不是同一个账户。
